## 2. IPSec 框架

IPSec 没有定义具体的加密和散列函数. IPSec 的做法是提供一个框架性的结构, 但每一次 IPSec 会话所使用的具体算法, 都是通过协商来决定, 与 Https, WEP, WPA 不同.

IPSec 可通过协商使用 3DES, 也可以通过协商使用别的加密协议. 在两个 IPSec 对等体之间的协议叫做 IKE

### 2.1 散列函数

散列函数也叫做 HASH 函数, 主流散列算法有 MD5, SHA-1, SHA-256, SHA-512 主要作用是验证数据完整性. 通过散列函数计算得到的结果叫做散列值, 这个散列值具有唯一性所以也被叫做指纹 Fingerprint. 

散列函数具有4个特点

1. 固定大小

    散列函数可以接收任意大小的数据，并输出固定大小的散列值。以 MD5 这个散列算法为例，*不管原始数据有多大，通过 MD5计算得到的散列值总是 128比特，而SHA-1的输出长度则为160比特。*

2. 雪崩效应

    原始数据就算修改*哪怕一个比特，计算得到的散列值也会发生巨大的变化。*

3. 单向

    只可能从原始数据计算得到散列值，*不可能从散列值恢复哪怕一个比特的原始数据。*

4. 冲突避免

    *几乎不能够找到另外一个数据和当前数据计算的散列值相同*，因此散列函数能够确保数据的唯一性。

#### 2.1.1 密钥化散列信息认证代码 HMAC

Keyed-hasd Message AUthentication Code

散列函数只能校验数据的完整性, 并不能判断数据的来源是否是合法用户, 如果有中间人攻击, 接收方并不能知道哪份数据是合法的

使用 HMAC 能进行*完整性验证*还有*源认证*.

1. 完整性认证 - 通过 MD5, SHA 散列

2. 源认证 - Pre-share Key 预共享密钥

在传输数据时, 通过 HMAC 预共享密钥 + 原始数据一起散列. 生成的值就可以用于源认证, 同时因为做了散列, 又可以保证数据完整性



### 2.2 验证数据完整性

1. 使用散列函数, 计算需要发送 "文件" 的散列值, 得到 "散列值一"

2. 对需要发送的 "文件" 和 '步骤1' 计算得到的 "散列值一" 进行打包, 发送给接收方

3. 接收方对收到的 "文件" 进行散列函数计算, 得到 "散列值二"

4. 接收方将收到 "文件" 中的 "散列值一" 和 "步骤3" 计算得到的 "散列值二" 进行对比, 如果两个散列值相同, 那么根据散列函数雪崩效应和冲突避免的特点, 确定 "文件" 完整性, 意味着整个传输过程没有被篡改.

## 3. 加密算法

加密算法主要分为两类

1. 对称密钥算法

2. 非对称密钥算法

### 3.1 对称密钥算法

加解密双方使用相同的密钥与算法进行加解密

- 优点:

1. 速度快

2. 安全

3. 紧凑

- 缺点:

1. 明文传输共享密钥, 容易出现中途劫持和窃听

2. 随着参与者数量增加, 密钥数量急剧膨胀

3. 密钥数量过多, 难以保存

4. 不支持数字签名和不可否认性

- 对称密钥算法的主流协议:

1. DES

2. 3DES

3. AES

4. RC4

### 3.2 非对称密钥特点

加密和解密使用不同密钥, 一个为私钥, 一个为公钥

1. Private Key 私钥: ==仅存储在本地==

2. Public Key 公钥: 公钥可以放在服务器上共享给属于这个密钥系统的所有用户与设备

公钥用于加密, 私钥用于解密, 除了用于加密解密还能用于数字签名.

1. 优点:

    - 不用担心密钥被劫持

    - 密钥数目少

    - 交互公钥前 不需要建立关系


2. 缺点:

    - 速度慢, 不紧凑

数字签名

特点: 通过私钥加密, 公钥解密, 能够有完整的源认证和不可否认性, 所以具备数字签名的特征

- 非对称密钥算法的主流协议:

1. RSA

2. DH

### 3.3 巧妙的加密方案

密钥使用**非对称加密**, 数据使用**对称加密**

### 4 封装协议

1. AH

Authentication Head IP 协议号为 51, AH 只能为数据提供完整性和源认证两方面的安全服务, 并能低于重放攻击. 

AH 不能为数据提供私密性服务, 不加密. 所以 IPSec VPN 基本不使用 AH

AH 也不能做 NAT

AH 对数据不加密, 仅仅做认证

2. ESP (使用最多)

Encapsulation Security payload 的 IP 协议号为50, ESP 能够为数据提供私密性, 完整性和源认证3大方面的保护, 并能低于重放攻击(反复发送相同的宝, 接收方由于不断地机密消耗系统资源, 实现拒绝服务攻击 DOS)

ESP 只能保护 IP 负载数据源, 不对原始 IP 头部进行任何安全保护

ESP 对数据即可加密也可以做认证

*AH 适用于实验场景(利于抓包), ESP 适用于生产场景*

### 5 封装模式

Transport 传输模式

传输模式只有1层头部

Tunnel 隧道模式

隧道模式会有2层头部

### 6. 密钥有效期

cisco 中 IPSsec 默认*3600*秒为一个周期, 每个周期会更新一次密钥, 可以手动修改时间.

加密数据越多越应该缩短密钥有效期, 因为使用次数多

加密数据越少越可以缩短密钥有效期, 因为使用次数少

PFS Perfect Forward Secrecy, Cisco 的密码更新技术, 是每个周期的密码没有任何连续性.
